# 知时

一个只面向 Android 的本地优先日程助手。内置有记忆的 AI 聊天小助手：用对话的方式告诉它你的安排，它提出日程操作，你一键确认后写入系统日历。

## 当前已实现

- 登录门禁：进入主界面前验证清华教学日历与网络学堂会话；优先复用已有登录。原生表单填写学号密码，仅向清华官方登录表单填入，由学校脚本完成 SM2 加密与浏览器指纹处理；验证码、二次验证保留官方页面。成功后凭据经 Android Keystore 加密保存于不参与备份的本机目录，会话失效时自动尝试恢复；退出登录清除凭据和学校会话。
- 功能面板：位于今天页日程卡片下方，随日程一起滚动；白色圆角、紫色图标的紧凑两行五列面板，大字体自动减少列数以避免挤压文字。作业角标仅使用近期完整读取的未提交状态，失败、部分读取和旧数据不显示数量；待交文件显示本机文件数量。底部仅保留今天、周、助手三个标签。
- 网络学堂作业：功能面板“我的作业”读取当前学期学生课程，按“未提交 / 已提交 / 已批改 / 全部”筛选并搜索课程或作业；显示截止、补交截止、可用的提交时间及线下/小组提示。AI 可按需查询当前状态，并结合日历提出待确认的学习安排。
- 清华课表与考试：功能面板中选择本科/研究生、明确的日期范围后读取教学日历，预览并勾选后确认导入系统日历。相同项目重复读取不重复导入，已导入后手动修改的标题、地点保留；导入后日程参与今天、周视图和 AI 按需读取。可以停止读取或清除本机登录状态。
- 今日日程卡片：点击日期打开日期选择器，非当天显示“回到今天”；所有日程均可点击查看完整详情，带任务清单时从详情进入清单。列表中的长标题、地点最多显示两行，完整内容可在详情查看；加载、未授权、空日程、失败分别显示相应提示和操作，切换日期不会把旧日程显示在新日期下。
- 单日日程天气：今天页日期旁仅显示可点击天气图标，点击或从功能面板进入完整详情，显示温度、风速、湿度、降水、更新时间及城市切换；未来日期显示对应日期预报。支持城市搜索、近似定位、刷新及 30 分钟缓存，无需天气 API Key，周总览不显示天气。
- 小云角落：移至功能面板，轻点云朵会弹跳、眯眼、散出星星并轮换一句轻松的话；可以收起或叫醒小云。动画只在点击时短暂播放，离开页面后取消。
- 天气参与排程：助手按需读取所选位置的逐小时预报，结合日历与降水、气温/体感、风速/阵风建议户外活动时段；普通室内安排不额外查询天气，现有日程调整仍需用户确认
- 全周日程视图：课表式时间网格（左侧时间轴、周一~周日七列、跨天日程按每日区间显示；全天日程单独小条展示）
- 校历周次：今天、周日程显示对应教学周。使用用户提供的 2026–2027 秋季校历，9 月 14 日为第 1 周的周一，10 月 24 日为第 6 周；每周一至周日一周，节假日连续计数。AI 理解“第七周周三”“第八到十周”及单双周，可据此查询或安排日程
- 清华大节作息记忆：每次文字或图片请求均携带用户提供的大课时间表，不受清空聊天或聊天历史条数限制；已知大节可直接换算起止时刻，第 5 大节原则上留作锻炼时间
- 周日程详情弹窗：点击任意色块或全天条目，完整查看标题、地点、起止日期时间和提醒；长文本换行且可滚动。普通日程可直接修改标题、地点并保存，有清单时提供任务清单入口；全天和重复日程可查看完整详情
- 任务清单：AI 检测到复习/预习任务时主动询问清单；带清单的日程可点进二级页逐条勾选
- 底部导航选中项紫色高亮
- 其他日程也可由 AI 附带清单（不主动询问）；任务清单二级页仅对有清单的日程开放，周视图的全部日程都可点击查看详情
- 手动删除：长按日程条目（有涟漪反馈）弹出确认框，删除时一并清理清单
- 清单手动编辑：二级页可直接添加/删除条目，不必绕道 AI
- 冲突检测：操作卡片自动标出与已有日程的时间重叠（红字提醒），AI 也会在回复中提示
- 日历按需读取：AI 根据问题和对话确定具体日期，再读取日程后回答；支持单日、自然周/月、历史或远期日期，以及移动日程时同时读取原日期和目标日期
- Token 用量：每条 AI 回复下方累计显示本次回答各轮请求的 tokens；闲聊无需向 AI 提供日程明细，查询只提供所需日期的数据
- 通知权限引导：设置页检测并引导开启提醒通知（Android 13+）
- AI 聊天助手：多轮对话、本地简要记忆与按需读原文；默认最近 6 条对话加相关资料，旧图片优先发送识别摘要，不重复携带 OCR 原文
- 停止生成：处理中可点击回复旁的“停止生成”或输入框右侧停止按钮，取消本次请求并恢复文字、图片草稿；中断后的迟到回复不会覆盖新对话
- 图片安排日程：优先在手机本机提取中文文字，由对话模型结合用户要求、校历和作息理解日程；文字足够时不上传原图，仅文字关系不清或识别失败时补看一次原图。后续核对日历只用文字资料，聊天内可查看识别日程并继续追问
- 助手可提出新增（CREATE）、调整（UPDATE）、删除（DELETE）操作，确认后逐条执行
- 地点字段全链路支持：AI 识别、编辑对话框、写入系统日历、卡片展示
- 读取 Android 系统日历，包括重复日程实例
- 可配置 GLM Base URL、API Key、模型、JSON 输出模式
- 模型列表选择：设置页填写 URL / Key 后点“获取模型列表”，可搜索并直接选择对话模型或图片日程识别模型；支持刷新，修改 URL / Key 后旧列表失效，接口不提供列表时仍可手动填写
- 逐条执行日程操作：成功的立即生效，失败的保留并说明原因；事件和提醒通过同一批事务写入，提醒失败时回滚事件，避免重试重复创建
- 移动日程时一起迁移清单完成状态
- API Key 使用 Android Keystore + AES-GCM 加密保存

## 技术栈

- Kotlin
- Jetpack Compose + Material 3
- Android `CalendarContract`
- OkHttp + kotlinx.serialization
- Android Keystore

## 开始使用

1. 用 Android Studio 打开 `D:\tmp\work\Zhishi`。
2. 等待 Gradle Sync 完成。
3. 连接 Android 8.0 以上手机，运行 `app`；首次使用先登录清华账号并完成学校验证，之后启动会优先复用本机登录。
4. 在“今天”页授予日历读取/写入权限。
5. 在“功能 → 设置”页填写：
   - Base URL：例如 `https://open.bigmodel.cn/api/paas/v4`
   - API Key
   - 模型名称：例如 `glm-5.3-flash`
6. 在“助手”页像聊天一样说出安排，例如“明天下午三点到五点在六教6A414上大学物理”。
7. 核对助手提出的操作卡片，可编辑或删除，点击“确认并执行”写入日历。
8. 从图片安排：在“助手”点击图片按钮选择图片并发送，也可补充“只安排周五的活动”等要求。App 先在本机提取文字，文字足够时直接核对日历，必要时才补看一次原图，随后通过操作卡片确认。处理中会显示本机提取、文字理解、补看原图和日历核对等阶段。点“查看识别日程”核对事项、时间、推断依据和待确认信息；可继续追问或调整。
9. 查看周日程详情：在“周”页点击任意小日程，弹出详情窗口。可完整查看长标题、地点，跨天事件显示真实起止日期；普通日程修改标题或地点后点“保存”写入系统日历，点“取消”放弃修改。保存仅更新标题、地点，保留原来的时间、时区、提醒、系统日历备注与清单；失败时保留编辑内容并显示原因。全天和重复日程在弹窗中只读，编辑请到系统日历处理。
10. 查看天气：在“今天”页点击日期旁的天气图标，或从“功能 → 天气”进入详情。首次点击“选择城市”，之后点城市名切换；也可点“使用当前位置”并授权近似定位。天气不依赖日历权限或 AI 设置，详情页可刷新，前后切换日期时随之切换；周总览不显示天气。

11. 按天气安排：先在天气卡片选择活动所在位置，再在助手中说“明天帮我选个适合跑步的时间”“检查周末户外活动是否要改期”或“下周三安排骑行，尽量避开下雨”。助手查询对应日期的天气及必要的日历，说明理由并给出待确认操作。异地活动先切换天气城市；使用定位时沿用上次取得的位置，发送消息不会重新申请定位。

当前版本为 0.9.34（版本码 51）。账号密码页内直接完成登录和进度展示，后台连续验证课表、作业服务，成功后自动进入首页；不再弹出独立进度页。学校要求可见验证码时才展开原验证表单，密码被拒则回到原生账号密码页修改。保留取消、重试及其他登录方式。图书馆预约默认官网直连，兼容已知官方 HTTP 链接升级 HTTPS；页面内可切换 WebVPN 或打开浏览器，拦截提示仅展示域名，不显示认证票据。已核对座位 CAS 和研讨间 authcenter 的公开认证入口，实际账号预约仍需手机验证。桌面图标改为紫色渐变底与白色日历时钟，适配圆形、圆角方形及系统单色主题图标，核心图形位于自适应图标安全区。切换到助手时直接定位最新一条消息，取消自动滚动动画，初始列表位置也设为最新消息。登录恢复继续使用原生进度页，学校网页在后台完成认证；INFO、网络学堂内容始终遮住，只有用户选择“完成学校验证”时才显示官方认证页面。两项受保护服务仍需实际验证成功后才能进入主界面。每阶段验证去重，不因页面自身跳转取消；同一表单不重复填交密码，重复完成回调不误判密码错误。每阶段限制40次导航、同一路径最多5次，隐藏验证45秒无进展则停止；超时/跳转循环需手动重试，不自动循环打开 INFO。保留教室资源、图书馆预约及作业功能。

教室资源为只读查询，通过现有学校会话为教室应用单独授权后读取 `portal3rd.do` / `pk.classroomctrl.do`。接口字段与六大节/七日状态协议核对自 [THUInfo basics.ts（cc1b581）](https://github.com/thu-info-community/thu-info-app/blob/cc1b58163159758b5407a5cb6e17f25808ea78e3/packages/thu-info-lib/src/lib/basics.ts) 和同版教室模型；独立 Kotlin 实现，不引入上游库。楼宇名称使用学校的 GB2312 查询参数，日期取学校表头，不把未开放周次或登录失败当作空闲。只有学校明确提供的课程/活动文字才显示为时段详情。当前教室数据不进入 AI 上下文，不修改学校预约或手机日历。

### 清华课表与考试接入

1. 功能 → 课表考试，选择本科生或研究生，核对起止日期。默认 2026-09-14 至 2027-01-17，来自用户已配置的秋季校历，不会自动推断其他学期；每次最多 183 天。
2. 首次启动在登录页填写学号密码并完成学校验证，之后优先复用会话。学校登录窗口依次验证教学日历和网络学堂；需要重新授权时，可点“学校登录”继续。学校密码只用于专用登录界面，不填入 AI 聊天或 AI 配置。
3. 阅读预览，核对完整标题、地点和北京时间，勾选需要的安排，授权手机日历后确认导入。学校未公布的考试不显示；空结果仅表示该日期范围没有返回数据，不能判断后续没有考试。课程的具体实际时间以学校返回数据为准。
4. 课表模块读取教学日历的主日历接口，包括其中已发布的课程和考试，不导入“个人日历”，不访问成绩、账单或体育预约接口；课程作业通过下述独立入口读取。二级课表和夏季选课系统不在本版接入范围，若学校主教学日历没有某门课，应在官方页面核实。不是后台自动同步；学校更改时间或地点后，重新读取会作为新的内容预览，不自动删除旧安排或覆盖手动修改，请核对处理。

SSO 思路参考用户提供的 [Table-Tennis-Checkin-Helper / api.py（e066274）](https://github.com/leverimmy/Table-Tennis-Checkin-Helper/blob/e066274456dd632e63e4a01745aaa5f8f0538072/api.py)：用户在官方页面登录，浏览器保留本机认证状态。体育系统 token 不能用于教学日历。教学日历协议、WebVPN 路径和应用标识核对自 [THUInfo 当前源码（cc1b581）](https://github.com/thu-info-community/thu-info-app/blob/cc1b58163159758b5407a5cb6e17f25808ea78e3/packages/thu-info-lib/src/lib/schedule.ts) 及同版本的 `core.ts` / `constants/strings.ts`。本项目独立实现 Kotlin 客户端，未引入或复制上游 TS 库实现。

学校会话通过 Android WebView CookieManager 留在应用私有目录，排除 WebView 数据的云备份和设备迁移；学校请求使用独立客户端，不携带 AI API Key，不把密码、Cookie、认证 HTML 或票据传给 AI。WebView 只允许已列明的学校 HTTPS 主页面，不开放 JavaScript 原生桥、文件访问或证书错误放行。教学日历分 21 天读取；任一批失败不展示成完整预览，可停止请求。导入使用稳定来源标记，标记和事件同一事务提交；分批失败后可重试并跳过已成功提交的项目。已导入日程仍会按原有 AI 日历读取规则提供给你配置的模型服务。

自动化验证覆盖日期与时间解析、课程节次合并、考试分类、SSO 失效、跳转白名单、取消与迟到响应、日历权限、保留手动修改及部分导入失败重试。未使用真实学校账号完成手机端登录验证，首次使用仍需用户在手机上验证实际学校认证链路。

### 登录后自动刷新与下拉刷新

进入 App 时先用只读接口验证已有学校会话，通过后进入主界面并刷新作业和课表，不自动写日历。没有会话或会话失效时，使用加密保存的凭据恢复官方登录，必要时由用户完成学校验证；未验证不进入主界面。没有保存凭据时显示原生登录页。每个官方凭据表单仅自动填入一次，学校返回登录失败表单时移除已保存的旧凭据，防止反复提交错误密码。旋转屏幕、切换标签、返回权限窗口或附件选择器不重复启动后台清单刷新。

学校登录窗口不以登录页 URL 或 HTTP 200 判断认证成功：先匹配学校页面，再通过对应的只读接口验证会话。网络学堂验证学生首页 CSRF 与当前学期数据；教学日历验证授权跳转与真实日历 JSONP。每项验证成功后立即刷新对应清单，再自动进入另一项授权；两项都完成后自动回到最初打开的清单，不额外重复读取。重复页面回调不会重复触发，退出或重新导航会取消未完成的验证，迟到结果不能继续推进登录流程。不是每次切换页面都自动访问学校接口。

手动更新统一为列表顶部下拉：作业在“我的作业”清单中下拉；课表在“功能 → 课表考试 → 查看课表”的预览清单中下拉。两个列表在首次未加载、空数据或失败状态下均保留可下拉区域，显示刷新进度，进行中再次下拉不重复发起请求。课表刷新失败或被停止时保留旧预览及上次更新时间，标明需要刷新，并禁用导入；成功后恢复。课表的日期范围和本科/研究生选项沿用设置值，刷新只更新学校来源预览，勾选确认后才写入手机日历。

### 网络学堂作业

在日程下方的功能面板点“我的作业”直达作业页签，点“待交文件”直达本机文件页签，也可在两个页签间切换。作业支持下拉刷新、停止读取、状态筛选，以及右上角展开搜索；学期与读取说明在菜单中查看，学校授权失效时可从菜单进入“学校登录”。文件页签不发起学校请求，从其他软件分享的新文件直接打开该页签；编辑或提交作业过程中收到分享则保留当前草稿。查看作业不需要日历权限或 AI Key；仅查看当前学期学生课程，不自动切换到任课教师/助教身份，不自动把作业导入日历。

作业数据来自网络学堂 `zyListWj`（未提交）、`zyListYjwg`（已提交待批改）、`zyListYpg`（已批改）三个列表。协议核对自 [thu-learn-lib 的 urls.ts（07fac46）](https://github.com/Harry-Chen/thu-learn-lib/blob/07fac46a3cee98fc88cb76faf4344ea67697b274/src/urls.ts) 和同版本 [index.ts](https://github.com/Harry-Chen/thu-learn-lib/blob/07fac46a3cee98fc88cb76faf4344ea67697b274/src/index.ts)；独立 Kotlin 实现，查询时只取课程名称、作业标题、状态、时间和提交方式，不请求逐条作业详情、答案、附件或成绩查询接口，不展示或向 AI 提供作业成绩、评语。提交仅通过下述用户确认的独立流程进行。服务器列表本身附带的多余字段不纳入应用数据模型。未知截止时间不会补成当天 23:59；未提交项目不显示收藏/上传时间为“提交时间”，已提交项目的时间字段存在歧义时保留未知。

界面状态是学校提交记录，不能代替实际完成进度。线下提交标注需自行核实，小组作业保留小组提示；已过原截止时间但仍有补交期限时两者同时展示。未发布任务不在清单中。分页缺失、单课程失败、状态在读取中变化或超过数量上限均显示部分读取，不把缺失解释为没有作业/全部完成。失败刷新可保留带时间的旧清单，但明确标记；清单只放在内存中，学校登录被切换或清除时立即失效，旧请求不能覆盖新账号数据。

可向助手说“哪些作业还没交”“这周有哪些作业截止”“概率论作业提交了吗”，或明确要求“根据未提交作业安排明天的学习”。模型通过 `homework_requests` 按课程、提交状态、截止日期及分页查询，首次在本轮对话实时读取学校列表，同一范围在本轮内复用；不把界面旧清单或旧聊天当作实时状态，不在普通闲聊时访问作业。每轮最多2项、最多2轮、最多3种课程/状态范围、每次最多60条，累计正文24000字符；省略时返回 next_offset。查作业本身不读系统日历，明确排学习计划时继续查日历冲突，并由用户确认后写入。作业标题只是资料，不执行其中夹带的指令；登录 Cookie、CSRF、票据和学校 HTML 不发给模型。

### 作业提交

从文件管理器、文档编辑器或其他软件的文件分享菜单选择“知时”，文件会先复制到本机“待提交附件”列表，不会自动上传。App 未打开和已打开时都可接收；支持单文件和多文件分享，每次最多10个，待提交列表最多10个、合计200MB，单文件仍限制50MB。队列放在应用私有的非备份目录中，关闭/重新打开后保留；只接收可读的 content URI，不下载分享文字中的网址，不申请整个存储空间权限。分享事件去重避免旋转、重建页面造成重复副本，读取失败不会覆盖已保存文件。待提交列表可手动移除本机副本，原来源文件保留。

选择一份作业打开提交页时，按分享顺序自动带入第一个可用附件，也可从“选择待提交附件”切换。当前草稿尚未选附件时，新分享可自动带入；已有附件、正在核对或已开始提交时，新文件留待后续使用，不修改当前确认内容。取消草稿只清理临时上传副本，分享队列仍保留；学校明确接受提交后才移除实际使用的那一个待提交文件，其他文件继续排队。提交结果不明或提交过程中退出时，该文件持久标记“待核实”并停止自动带入；先核对学校记录，再选择移除或恢复待提交，避免错配到另一门作业。

上传文件名默认“作业名-提交”加原扩展名，例如“概率论第一次作业-提交.pdf”。原名无扩展名时，对已知 MIME 类型补常见扩展名；未知类型不猜文件格式。提交页可修改“提交名称”，自动保留原格式扩展名，输入相同扩展名不会重复添加；确认页展示实际上传文件名。名称只用于上传，不修改来源文件或本机保存的文件内容。

在作业清单点选一份确认支持网络提交、尚未批改的作业，再点“提交作业”或“重新提交”。选择一个附件，可从待交文件中选择；默认折叠改名输入框，点“改名”修改提交名。点“核对附件”后核对课程、作业、完整原文件名和上传文件名，再点“确认提交”。不提供正文输入；无附件不能进入确认。重交可能清空学校原有正文并替换附件，需要先勾选覆盖确认，确认弹窗再次明确提示。线下提交、提交方式未知或已批改的作业请到学校页面核实。原截止时间与补交时间均显示，是否接受补交最终由学校决定。

应用附件上限为50MB，每次提交仅支持一个非空文档；学校可能有更小的大小或类型限制。使用 Android 文件选择器授予的单文档权限，不申请整个存储空间权限。用于本次上传的附件复制到本机私有缓存中，移除、退出草稿或成功提交后删除临时副本，来源文件保留；来自分享的持久待提交副本按上述队列规则处理。提交文件仅发送到学校，不提供给 AI；AI 聊天没有提交工具，也不能触发或代替用户确认。

发送前再次读取当前学期相应课程的全部作业状态，核对真实学生作业 ID、课程、标题、提交方式、批改状态及可用的提交时间，状态变化或读取不完整时停止提交，要求重新核对。独立提交方法仅允许向网络学堂 `/b/wlxt/kczy/zy/student/tjzy` 上传 `xszyid` / `zynr` / `fileupload` / `isDeleted=0`，其中应用提交流程的 `zynr` 固定为空。保留只读列表接口限制，使用一次性 multipart 请求体，禁用网络自动重试与重定向，不因超时或登录失效自动重发附件。收到学校 JSON `result=success` 后才显示已接收并刷新状态。

断网、超时、重定向、无效响应等导致结果无法确认时，显示“结果待核实”并阻止重复点击；先返回列表重新读取完整学校记录，再决定是否重交。不能把“没有收到回复”解释为学校没有收到文件。提交中禁用编辑/再次确认；账号变化时清除编辑数据、取消旧请求并忽略迟到结果。真实账号的首次登录、文件类型限制与实际提交结果仍需在手机上验证，本地测试不使用真实学校账号或真实作业提交。

天气来自 [Open-Meteo Current Weather](https://open-meteo.com/en/docs)，属于模型估算的当前天气，不是手机自带天气应用的数据，也不是某个气象站的分钟级实测。位置可手动从 [Open-Meteo / GeoNames 城市搜索](https://open-meteo.com/en/docs/geocoding-api)结果中选择，同名城市显示地区供核对；默认不猜测城市，也不自动申请定位。定位只申请 `ACCESS_COARSE_LOCATION`，使用系统定位接口，不依赖 Google Play；坐标约取到小数点后两位。没有可用定位服务、权限被拒或定位超时（12 秒）时可继续手动选城市，不申请后台定位。

单日页顺序为日期与日程列表、天气卡片、小云角落；周总览不显示天气。天气使用与应用主题一致的渐变圆角卡片，今天突出当前温度/体感与天气图标，未来日期突出最低/最高气温，并以小色块展示可用指标。默认不占用额外按钮行，城市名称可点击切换，定位与数据时间收纳进“天气详情”；首次未选城市、加载中、刷新失败、缓存过期和部分预报缺失均有明确显示，数据缺失不补零。来源链接保持可用。选择今天时显示当前天气，展开后可查看湿度、风速、对应过去时段的降水、数据时间、时区及缓存时间；选择未来 15 天内的日期时按日程时区汇总对应日期的逐小时预报，显示气温范围、天气变化、当日各小时降水概率的最大值和最大风速（并非整日下雨概率）。次日零点的降水概率用于当天最后一小时，次日零点的气温不混入当天范围。过去或更远日期明确提示暂无数据，不再显示今天的天气。缺时段、缺指标显示部分预报；未知天气代码不当作晴天。快速切日或切城市时取消旧请求，迟到结果不能覆盖新日期/城市；未来日期沿用已选位置，不会因翻页重新定位。未来预报按城市、日期和日程时区在内存中缓存 30 分钟、最多 16 份，缓存失效或刷新失败会提示。接口按摄氏度、m/s、mm 和 UTC Unix 时间戳读取，不二次叠加时差。

城市选择与最近一份天气保存在本机。新鲜缓存复用 30 分钟，App 在前台时约每 30 分钟检查并刷新，也可手动刷新；退到后台停止定时任务和进行中的定位。刷新失败保留同一位置的旧数据并明确提示错误，过期缓存会标记；切换城市或更改搜索词会取消旧 HTTP 请求，迟到结果不能覆盖新城市。天气请求单独访问公开接口，不附带 AI API Key、聊天或日历内容。排程时向 AI 提供所选位置的名称、地区，以及按需查询的日期和逐小时预报；不会自动把当前天气快照当作未来天气。来源链接在卡片内展示。免费开放接口面向个人非商业使用，受服务可用性与调用额度限制，见[官方说明](https://open-meteo.com/en/pricing)。

排程天气查询使用 [Open-Meteo 逐小时预报](https://open-meteo.com/en/docs)，只查询今天起 16 天内的日期，每个范围最多 7 天，每轮最多 3 个范围、每次提问最多 3 轮，合计不超过 16 个日期。日期按手机日程时区解释，时间戳按 UTC 转换。降水量、降水概率和阵风归属于截至预报时刻的前一小时，补取次日零点以判断当天最后一小时（预报范围最后一天可能缺少该点，明确标记不完整）；跨日活动需读取两天。缺行、空指标、未知天气代码、过期数据、错误城市/时区及服务失败均不能解释为好天气。超出范围不外推；天气数据和获取时间只在本轮提问内复用，不沿用旧聊天或当前天气缓存。户外操作漏查时会补查，但现有日程不会因天气刷新自动移动或取消；用户明确提出必须满足的天气条件时，要求模型在天气不足时先询问，不生成依赖该前提的操作。最终仍需确认卡片；这是模型预报，不能保证活动时刻的实际天气。

生成过程中，回复状态栏显示“停止生成”，输入框右侧发送按钮切换为停止图标。停止会取消当前生成协程及其 HTTP 请求，包括等待模型响应和接收响应体的阶段；本机 OCR、补图加载或日历查询阶段也可停止等待，不再继续调用后续模型。原生 OCR 等已经开始的本机任务可能自然运行到结束，但结果会被忽略并释放资源，不会再生成日程或覆盖草稿。停止后撤回本次未完成的提问、保留此前聊天并恢复原始文字和图片，可立即修改后重新发送；主动停止显示“已停止生成”，普通网络失败仍保留实际错误提示。每次生成有独立标识，旧请求的迟到进度、日历和回复不能覆盖新请求。已点击“确认并执行”的日历写入会继续完成，期间不显示停止生成入口。

AI 固定记忆中的清华大课（大节）作息采用用户提供的以下时间，文字对话和图片排课共用：

| 大节 | 时间 | 说明 |
| --- | --- | --- |
| 第 1 大节 | 08:00–09:35 | |
| 第 2 大节 | 09:50–12:15 | 保留用户指定的完整时段 |
| 第 3 大节 | 13:30–15:05 | |
| 第 4 大节 | 15:20–16:55 | |

一门课一般占一个大节（2 学时），课间短休息不单独拆分日程；具体起止时刻优先，不按“2 学时”改写上述时间。例如“第七周周三第 2 大节”直接对应 2026-10-28 09:50–12:15。自动推荐排课避开第 5 大节，用户或课表明确指定该时段时尊重原安排；不自动创建锻炼日程。小节与大节含义不明或使用其他学校作息时才询问，用户明确提供的实际时间优先。

设置页可先填写 URL 和 API Key，再点“获取模型列表”，无需先保存或填写模型名称。列表中可搜索并点击选择；两个模型框右侧的箭头分别选择对话模型和图片日程识别模型，最后点击“保存”生效。提取出的文字始终由对话模型处理；补看原图才调用图片模型。图片模型留空或点击“跟随当前对话模型”时，补图使用已选择的对话模型；也可单独选支持图片输入的模型。客户端按常见的 [`GET /models` 格式](https://api-docs.deepseek.com/api/list-models/)读取接口返回的模型 ID；若返回图片输入能力声明，则展示并用于图片模型选择，未声明时不凭名称推断。列表可见不代表每个模型已通过调用测试；对话模型可通过“测试连接”验证。服务不提供模型列表、Key 无权查看或网络失败时显示相应提示，保留手动输入。

本机文字识别采用[ML Kit 内置中文模型](https://developers.google.com/ml-kit/vision/text-recognition/v2/android)，识别模型随 APK 打包，无需另配 OCR API 或在首次使用时下载模型。本机识别得到的文字以 `image_ocr_text` 提供给对话模型，校历和大节作息仍可直接使用；本机识别无结果、失败、超过 8 秒或文字超过 30000 字符时自动回退原图理解。

文字已足够确定日程时，后续请求都不读取或上传图片文件。只有文字缺少关键关系（例如课表行列、箭头对应不明）时，模型才返回 `{"image_request":{"reason":"具体缺失关系"}}`，App 此时才懒加载原图，并只在下一次请求中附上 `image_url` Base64 Data URL。补看原图必须给出完整的 `image_analysis`，随后读取日历和生成操作回到纯文字；同一提问最多补看一次。补图请求中夹带的日程操作不执行，也不提前读取夹带的日历请求。重复请求原图时改为请用户补充，不循环上传；原图查询未给出识别资料时明确报错，保留草稿供重试。

识别结果保存在 `image_analysis` 中，本机 OCR 原文保存在 `image_text` 中，供后续文字追问使用。OCR 原文可能有误，补图校正后的资料优先。图中本来没有的日期等信息仍需询问用户，不盲目请求原图或编造。仅缺年份但可由日期、星期和上下文可靠确定时，允许说明依据后推断。原图按下述规则留在本机供预览和必要时补看，不会因文字足够就丢失聊天附件。

[GLM-5.3-FlashX 官方说明](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash)确认其支持图片和 Base64 Data URL。选择 `glm-5.3-flashx` 为对话模型、图片模型留空即可使用；该系列请求使用 `temperature: 1`，连接测试为思考输出预留足够预算。升级到 0.9.3 后保留现有 URL / API Key / 对话模型，图片流程默认跟随对话模型，不自动沿用旧的 OCR 专用模型设置。旧聊天记录中的 OCR 资料仍可用于追问。

原图最大 20MB，在本机按方向校正、缩放并重编码为最多 2MB 的 JPEG，保存在应用私有目录；聊天 JSON 只存图片文件名、OCR 原文和识别日程，不存图片 Base64。替换未发送图片、清空聊天或淘汰旧记录时清理对应副本。发送失败会恢复文字和图片草稿以便重试。每条回复的 token 用量累计文字理解、必要时的原图理解和日历读取各轮模型请求；本机 OCR 不消耗模型 tokens。内置识别模型会增大 APK，实际提速幅度取决于图片、手机和模型服务耗时。

## 上下文与本地记忆（0.9.13）

旧消息由本机提取简短原句、角色、时间、关键日期片段与历史操作提示，不另调 AI 生成摘要，避免额外模型请求。旧助手推测保留助手来源，不提炼成用户事实；最新明确说明优先于旧偏好。简要记忆随聊天保存，即使部分原文超出 100 条，仍可留下偏好摘录，但不是无限记忆，也不能据此重建已淘汰的原文。

默认发送最近 6 条消息（本次最新消息完整保留；此前长消息最多展示约 2000 字符并标明省略）、最多 8 条限长记忆及最多 2 张相关旧图的资料。同等相关的图片优先较新来源并保留消息 ID，指代不明时仍需确认。旧图有 `image_analysis` 时不同时发送 `image_text`，旧版仅存 OCR 时可回退文字资料。新图片取得完整 `image_analysis` 后，后续核对轮次使用一份更新后的图片资料，移除本次首次 OCR 大段文字，原文仍可按消息 ID 读取。聊天附件、原文和查看识别日程的功能继续保留。

需要省略的原文时，模型可以请求指定消息的字段，不读取或上传旧图二进制：

```json
{"context_requests":[{"kind":"history","message_id":123,"field":"image_text","offset":0,"limit":4000}],"reply":"","actions":[],"questions":[]}
```

`field` 支持 `text`、`image_analysis`、`image_text`、`actions`；默认优先识别摘要，仅核对原字或摘要缺细节时取 OCR。每轮最多 3 项、每次提问最多 2 轮，字段读取每次 1–8000 字符、累计最多 32000 字符，重复的同页读取复用本轮结果。返回 `offset`、`next_offset`、总长度与完整性标记，部分读取不能当成完整原文。原文已淘汰、字段缺失或预算耗尽时明确返回不完整，并向用户保留相应警告，不假造细节。只有必要的补读会增加一次模型请求。

校历与大节也可本机查询，不访问个人日历：

```json
{"context_requests":[{"kind":"academic","week":7,"weekday":3,"period":2}],"reply":"","actions":[],"questions":[]}
```

上述请求返回 2026-10-28 09:50–12:15。可只传 `week` 或 `period`，也可传 ISO `date` 查询周次；跨年日期、本科寒假与未配置学期均按本机校历处理，拒绝非法周次、大小节编号、冲突日期或未知学期参数。没有明确为“大节”的编号仍需确认含义。完整周表只有明确需要时才展开。

固定规则合并精简，较稳定规则放在提示开头，当前时间、页面日期与读取状态放在后面。此调整减少重复输入，不承诺任何服务一定命中缓存。历史日历、天气和执行标记始终只是旧资料：实际日程查询及新建/移动/删除继续按本次问题读取日历，天气继续按所选城市和候选日期查本轮预报，操作仍须用户确认。读取旧原文、校历、日历和天气可在同一轮请求，但读取请求附带的操作不会执行。

## 模型接口约定

客户端使用 OpenAI-compatible 的 Chat Completions 形式，默认携带最近 6 条对话、本地简要记忆及相关图片摘要：

```text
POST {baseUrl}/chat/completions
Authorization: Bearer {apiKey}
```

模型被要求只返回 JSON：

需要日历数据时，模型先返回读取请求，客户端读取后在同一轮对话中继续调用模型：

```json
{
  "calendar_requests": [{"start_date": "2026-11-01", "end_date": "2026-11-30"}],
  "reply": "",
  "actions": [],
  "questions": []
}
```

日期范围包含起止两天；每轮最多 4 个范围，每次提问最多 3 轮读取、累计 366 个不同日期。每个范围最多向 AI 展示 200 条事件，超出时标记结果不完整，允许继续缩小范围读取。未读取或未完整读取的日期不能当作没有日程；已知校历与对话都无法确定日期的考试周、假期等先询问日期。日历读取通常会增加一次模型请求及相应等待时间。

本机保留完整秋季校历（18 周，2026-09-14 至 2027-01-17），文字和图片共用。0.9.13 起仅提供学期起止、当前周次、6 个大节固定作息及问题明确涉及周次的本机换算；不再默认展开整张周表。仍可直接发起周次读取，由本机换算而非依赖模型日期运算：

```json
{"calendar_requests":[{"week":7,"weekday":3},{"start_week":8,"end_week":10}]}
```

上述两项分别对应 2026-10-28 当天，以及 2026-11-02 至 2026-11-22。`week` 单独使用表示整周；`weekday` 为 1（周一）至 7（周日），仅用于单周。返回结果仍使用实际起止日期；超出 1–18 的周次、倒序范围或与显式日期冲突的请求会报错，不读取错误日期。跨年后的 2027-01-01 仍是第 16 周。第 18 周之后显示寒假（本科生校历为 2027-01-18 至 02-21），不外推第 19 周；教师、研究生寒假范围不同，AI 会确认身份。未配置的其他学期或学年显示“未配置校历”，需要补充对应校历。

## 当前边界

- 修改或删除重复日程、全天日程时会被本地保护逻辑拒绝，需在系统日历中处理。
- 任务清单及其勾选状态只保存在本机（卸载或清除数据后丢失），不写回系统日历。
- 聊天原文保存在本机 SharedPreferences，最多 100 条；另保留有来源和时间的简要记忆（最多 64 条，优先保留最多 24 条偏好摘录及最近 40 条摘录）。默认发送最近 6 条消息和限长的相关记忆；清空聊天同步清除记忆，固定校历/作息仍保留。
- 还没有本地数据库，日程的唯一来源是系统日历。
- 还没有账号、云同步和服务器。
